# 代码质量规则

## 适用范围

本规则用于 Apply 阶段的业务代码修改。

目标是：

- 保持实现简单；
- 保持类型和领域语义明确；
- 控制局部复杂度；
- 避免无关重构；
- 让后续 Agent 能快速理解和安全修改代码。

## 精确实现

遵循 KISS、YAGNI、DRY。

- 只实现当前 Specs 和 Task 要求的能力；
- 不为单次使用场景提前创建抽象层；
- 不增加没有明确需求的配置项或扩展点；
- 不顺手修改与当前 Change 无关的代码；
- 不复制已有业务逻辑形成第二套事实来源。

发现明显技术债但不属于当前 Change 时，应记录，而不是顺手扩大修改范围。

## 类型

核心业务代码保持严格类型。

- 不使用无明确结构的 `dict` / `object` / `Any` 传播领域数据；
- 外部不可信输入必须先经过显式校验再进入领域逻辑；
- 跨模块数据通过明确 DTO、Schema 或契约传递；
- ORM Model 不作为跨领域或 API 公共契约。

确实无法避免弱类型的边界代码，应将其限制在最小范围，并立即转换为强类型对象。

## 命名与领域语义

如果存在 `docs/glossary.md`：

- 实体；
- 状态；
- 角色；
- 权限；
- 业务动作；

必须优先使用统一领域术语。

名称应表达业务意图，而不是只描述技术实现。

## 注释

注释主要用于解释：

- WHY；
- 不明显的业务约束；
- 不变量；
- 架构或兼容性决策。

不要用注释重复代码已经清楚表达的 WHAT。

已经记录为明确 Decision 的约束，不得在没有重新确认设计的情况下擅自“修正”。

## 函数复杂度

默认工程预算：

- 纯函数优先控制在 30 行以内；
- 编排函数优先控制在 50 行以内；
- 认知复杂度优先 `<= 10`；
- 嵌套层级优先 `<= 3`；
- 参数数量优先 `<= 5`。

这些数字是复杂度预警线，不是为了凑数字进行机械拆分。

超过预算时应判断：

1. 是否包含多个业务责任；
2. 是否可以提取独立纯逻辑；
3. 是否存在隐藏的数据或状态耦合。

函数超过 100 行时，默认不得直接提交，除非存在明确且合理的不可拆分原因。

## 纯逻辑与副作用

业务计算与外部副作用应尽量分离。

纯逻辑负责：

- 规则判断；
- 计算；
- 状态转换；
- 数据变换。

副作用负责：

- 数据库；
- 网络；
- 文件；
- 时钟；
- 随机数；
- 外部服务。

这样可以让核心规则通过确定性单元测试验证。

## 状态管理

禁止通过模块级可变全局状态承载业务状态。

跨边界 DTO 和领域事件优先不可变。

存在三个及以上显式业务状态时，应评估是否需要：

- 明确状态集合；
- `VALID_TRANSITIONS` 或等价机制；
- 集中式状态转换入口。

不得通过任意字段赋值绕过领域状态约束。

## 文件与模块规模

文件应保持单一关注点。

默认将 300 行视为代码组织预警线，而不是机械限制。

超过时优先判断是否存在：

- 多个不相关职责；
- 可以形成独立模块的领域概念；
- 基础设施与业务规则混杂；
- 多个 Slice 被错误集中在同一文件。

## 修改范围

单个原子 Task 的核心业务修改优先控制在少量文件内。

预计涉及超过 8 个文件时，应重新检查：

- Task 是否过大；
- Design 是否需要进一步切片；
- 是否存在不必要的耦合。

生成代码前不要为了“了解项目”一次性读取大量无关文件。

## 重复代码

不要为了避免任何重复而过早抽象。

当重复代码代表同一业务概念，并且已经形成稳定模式时再进行抽象。

不得为了 DRY 把不同领域含义但结构相似的代码强行合并。

## 提交前自检

完成原子 Task 后至少检查：

1. Diff 是否全部属于当前 Task；
2. 类型是否明确；
3. 是否引入无必要抽象；
4. 是否存在明显重复业务逻辑；
5. 是否产生新的跨领域内部依赖；
6. 是否存在未受控副作用或全局状态；
7. 是否存在明显复杂度超限；
8. 对应验证是否已经通过。

## 技术栈专项规则

本文件定义跨技术栈长期成立的代码质量原则。

不得仅根据历史规则、模板或 Agent 经验假设项目当前使用：

- Python / mypy / Pydantic；
- TypeScript / tsc；
- 某个 Web Framework；
- 某个 ORM；
- 某个 Linter 或 Formatter。

具体语言、框架、类型检查器和静态分析规则必须以当前项目真实配置为准。

当项目技术栈稳定后，如果某项约束只适用于特定语言或框架，应建立独立专项规则并按需加载，而不是继续膨胀本文件。
